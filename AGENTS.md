## Build

Initialize submodules first:

```bash
git submodule update --init --recursive
```

On this machine, the default `make` needs explicit serial HDF5 include/library paths and a free-line-length flag:

```bash
make -j4 \
  FFLAGS='-O3 -fopenmp -ffree-line-length-0 -DVERSION=\"main:4d310c14970d9b47fa6f40dfde78d03b61afb526\"' \
  LFLAGS='-I/usr/include/hdf5/serial -L/usr/lib/x86_64-linux-gnu/hdf5/serial -lgsl -lz -lhdf5_fortran -lm -ldl -lblas -llapack'
```

Then install the executable symlink:

```bash
make install
```

This creates `/home/mengziyan/bin/NuHamil.exe`, pointing to `exe/NuHamil.exe`.

## What NuHamil Does

NuHamil is mainly an interaction/matrix-element generator and converter. It takes nuclear interaction inputs, such as the bundled NN files under `input_nn_files/`, transforms them to harmonic-oscillator basis matrix elements, optionally applies SRG/other processing, and writes matrix-element formats for many-body solvers.

For the Bigstick workflow, the relevant chain is:

```text
raw NN interaction -> NuHamil -> two-body matrix elements (.MFDn/.me2j.gz/.snt) -> Bigstick
```

Bigstick then does shell-model diagonalization, wave functions, densities, etc. NuHamil is not primarily the spectrum diagonalizer for the final shell-model problem.

## Running Jobs

NuHamil reads a Fortran namelist input file:

```fortran
&input
  rank = 2
  hw = 30
  renorm = "bare"
  lambda = 1.8
  Operators = "hamil,Mmoment_IA,Qmoment_IA,Radius"
  bra = 1, 1, 0, 0
  ket = 1, 1, 0, 0
  trans2lab = False
  NNInt = "N3LO_EM500"
  input_nn_file = "/home/mengziyan/NuHamil-public/input_nn_files/N3LO_EM500_kmax8_N100_Jmax8.bin"
&end
```

Run it with:

```bash
NuHamil.exe input.dat
```

The Python scripts in `exe/` generate these namelist files and then call `NuHamil.exe`.

## Generating Two-Body Matrix Elements

The main script for two-body matrix elements is:

`exe/NuHamil_2BME.py`

By default it writes `.me2j.gz`:

```python
ext_2bme = ".me2j.gz"
```

For a Bigstick/MFDn-style output, change this to:

```python
ext_2bme = ".MFDn"
```

For a quick test on a new platform, reduce the model space first, for example:

```python
set_input(params, hw=16, emax=2, e2max=4)
```

Then increase toward production settings such as `emax=14, e2max=28` only after the workflow is verified.

## Converting Existing `.me2j.gz` to `.MFDn`

If the user already has a two-body Hamiltonian in `.me2j.gz` format generated by NuHamil, it can be converted to `.MFDn` using `file_convert` mode. This is a format conversion/truncation, not a way to regenerate missing larger-space matrix elements.

Example namelist:

```fortran
&input
  file_convert = .true.
  rank = 2
  Operators = "hamil"

  hw = 16
  emax = 14
  e2max = 28
  lmax = 14

  emax_convert = 14
  e2max_convert = 28
  lmax_convert = 14

  file_name_nn_original = "/path/to/input.me2j.gz"
  file_name_nn_converted = "/path/to/output.MFDn"
&end
```

Run:

```bash
NuHamil.exe convert.in
```

Important details:

- The original `hw`, `emax`, `e2max`, and `lmax` must match the source `.me2j.gz`.
- `emax_convert/e2max_convert/lmax_convert` should be less than or equal to the source space.
- This path is for scalar two-body Hamiltonian files. General operator files such as `.op.me2j.gz` may not be compatible with `.MFDn` output.

The bundled `exe/file_converter.py` documents the mode, but currently has a syntax issue (`def main()` lacks a colon) and empty default filenames, so writing a namelist by hand is more reliable.
